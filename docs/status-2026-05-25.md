## 9. EverRun 工作流：已修 + 待修

**已生效的修复（这一周）：**
1. `extract_final_status_digest()` 把 coder stdout 摘要喂给 planner（修复 evidence summary 看不到证据）
2. `max_new_files` 从 hard gate 降级为 telemetry warning（不再误伤）
3. `permission_gate_blocked_after_success` 识别为 false alarm（不再升级 reject）

**剩余待修的 evidence pipeline bug：**

`impl-result.json` 的 git 三字段不一致：
```
status_short:   "M README.md"  <- OK
changed_files:  []              <- 错（应有 README.md）
diff_stat:      ""              <- 错（应有 +78/-4）
```
触发条件：只动 1 个文件且文件是 modified（不是 added）。Planner 看到矛盾被迫升级 human_review。这影响**任何小型 docs/metadata pack**。

**已建立的协作模式（这一周锤出来的）：**
- Pack accept 后**必须立即 commit**（否则下一个 pack 启动时 planner 把工作树残留误判为本轮 scope 违规）
- 文档 pack 优先纳入手动 mv -> commit 兜底（everrun git evidence 对 modify-only diff 不可靠）
- ruff/mypy 加入 validate 列表会让 baseline 错误结构性阻塞 metadata pack——已通过独立 lint baseline pack (0005) 解决

## 10. 风险与建议

**当前无 P0/P1 风险。** v0.1 是稳定基线，可被外部依赖。

**推荐下一步（按价值排序）：**

| 候选 | 价值 | 复杂度 | 建议 |
|---|---|---|---|
| Tag v0.1.0 | 锚定稳定基线 | 低 | **现在就做** |
| evaluation-harness | 与现有 storage 闭环最近 | 中 | 下一批主推 |
| examples 扩展（多 policy / 多 tool） | 用户上手摩擦 | 低 | 与 evaluation 共做 |
| adapters | framework 集成需求 | 高 | 等 evaluation 之后 |
| runtime-server | HTTP/远程引入 | 高 | 等 adapters 之后 |
| regression | 跨 run 比较 | 中 | 等 evaluation 之后 |

**不建议现在做的事：**
- 立刻起 adapters 或 server——这两批引入 framework/HTTP 依赖，应等 evaluation/regression 把可观测性闭环
- 把 ruff/mypy 加进 v0.1 pack 模板——会反复触发 baseline 阻塞模式
