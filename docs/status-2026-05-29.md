## 3. 产品视角（PM）

### 3.1 这次定位升级是真的，不是文档秀

**关键 ADR 摆出三个明确决策：**

| ADR | 决策 | 战略含义 |
|---|---|---|
| [ADR-0001](docs/decisions/ADR-0001-ailuros-as-governance-runtime.md) | Ailuros = **governance runtime**，不是 agent framework / UI 平台 / 通用工作流引擎 | **划定护城河**：不卷 framework 赛道，专注治理 |
| [ADR-0002](docs/decisions/ADR-0002-clarify-as-reference-app.md) | Clarify = **reference app**，不是 peer core | **避免 Clarify 反向污染 core**——这是 framework 产品最常见的死法 |
| [ADR-0003](docs/decisions/ADR-0003-evidence-first-integration.md) | Clarify 集成 = **evidence-only**（Phase 1） | **拒绝过早 platformization**——不开 HTTP write API、不做浏览器实时拦截 |

> **PM 解读**：这是教科书式的"产品边界声明"。SDD 时代的 framework 90% 死于"什么都想做"。Ailuros 把不做什么写进 ADR 比写进 README 重一个量级——ADR 是工程团队拒绝需求的合法武器。

### 3.2 路线图从"技术 todo"变成"价值阶段"

[roadmap.md](docs/strategy/roadmap.md) 把发展分成 5 个 phase：

```
Phase 0 (v0.1) ─ Core 稳定                                            ✅ 已完成
Phase 1       ─ Clarify evidence integration (evidence-only)
Phase 2       ─ Governed LLM Call
Phase 3       ─ EverRun Loop
Phase 4       ─ radarCreation Vertical
Phase 5       ─ Platformization (server / REST / dashboard / adapter ecosystem) ← 显式 defer
```

> **架构师警示**：Phase 5 写着 "explicitly deferred"——意味着我在 [status-2026-05-28 §6](docs/status-2026-05-28.md) 写的 "LangChain adapter / HTTP 鉴权 / Postgres 后端" 这些建议**全部被产品方向否决了**。这不是坏事，是**产品聚焦**。我之前的建议偏 platform thinking，新文档明确说不走那条路。

### 3.3 三个 Proof Path（一核三证）模型

[product-line-thesis.md](docs/strategy/product-line-thesis.md) 的核心心智模型：

```
                  Ailuros Core
        (governance runtime — application-agnostic)
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
    Clarify        EverRun     radarCreation
   (浏览器证据)   (持续运行)     (垂直行业)
```

这个模型对 PM 很有用：
- **三种风险都被独立证明**：一个证浏览器/证据场景、一个证持续 agent 自治、一个证垂直深度
- **任何一条 proof path 失败都不致命**——核心还在
- **避免单一 reference app 绑架核心架构**

### 4.4 adapter 层最有意思的演化

[adapters/base.py](src/ailuros/adapters/base.py) 最新长成这样：

```python
class _RuntimeProtocol(Protocol):
    def before_tool_call(...): ...
    def record_tool_result(...): ...  # ← 新增

class LocalCallableAdapter:
    def execute_tool(self, fn, context):
        decision = self._runtime.before_tool_call(...)
        if not decision.allowed: return blocked
        result = fn(**context.arguments)
        self._runtime.record_tool_result(...)  # ← 新增：完整闭环
        return allowed
```

**架构演化**：从"只调 before"变成"before + after 都通过 protocol"。这是**为外部 framework adapter 开门**——LangChain/LlamaIndex 适配器只要实现这个 protocol，就能拿到完整治理 lifecycle。

> **观察**：roadmap 把 LangChain adapter defer 到 Phase 5，但 contract **已经做好了**。这是正确的：**把接口锁死，把实现延后**——避免接口被 framework specific quirks 污染。
